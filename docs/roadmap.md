# Roadmap and evidence gates

The implementable local ledger is complete through schema v6. It is an
agent-first evidence ledger, not a claim that object recognition, insurance
coverage, or effortless adoption has been proven in the world.

## Implemented and covered by code and tests

- Evidence-backed ownership, absence, lifecycle, corrections, and explicit
  unknown event dates.
- Conservative compatibility, condition-aware operational advice, aliases, and
  scoped task-context retrieval.
- Crash-recoverable JSONL transactions, atomic proposals, media, export,
  restore, and offline replica application.
- Separate canonical data, media, runtime, and Obsidian catalogue boundaries.
- v1-v5 forward migration policy to current schema v6.
- Passive capture preparation, adapter protocol, immutable crops, duplicate
  ranking, review, and bounded proposal application.
- Direct-current-physical-check images only for insurance photography;
  provenance-bound receipt and appraisal documents; decoded media; and
  deterministic package generation and validation without invented readiness.
- Checked spatial profiles, append-only item dimensions, fit, free volume, and
  deterministic packing that preserve unknown measurements.
- Kit reviews, condition-aware torque and compatibility advice, and measured
  upkeep records.
- Scope-safe CLI and least-privilege stdio MCP profiles that share the same
  retrieval and reasoning paths.
- A CI test matrix for Ubuntu and macOS on Python 3.11, 3.12, 3.13, and 3.14,
  plus a separate public-boundary, wheel, secret, and link audit job.

## Evidence that source tests cannot manufacture

1. A manually checked real-room corpus must measure segmentation, extraction,
   barcode, and duplicate-match error. The bundled corpus is synthetic and
   proves the measurement path, not real-room accuracy.
2. Four or more weeks of ordinary use must measure correction count, review
   count, and elapsed upkeep. The harness is synthetic and proves aggregation,
   not longitudinal usability.
3. Independent users and restores on other machines must establish practical
   compatibility and reveal missing adapters.
4. An insurer in the relevant jurisdiction must evaluate a real package. A
   valid package is preparation material, not coverage or a claim outcome.
5. A release candidate still needs root-owned live/private and public-boundary
   evidence. No public release is claimed here.

## Next evidence campaign

Use a private instance to reconcile real spaces, keep uncertain extraction at
the review boundary, and record checked cases in a private benchmark corpus.
Record upkeep through the maintenance commands rather than estimating it later.
When root-owned live and public checks exist, run the release-acceptance batch
from audited clean history without publishing private data.
